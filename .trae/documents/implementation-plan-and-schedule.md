## 0. 两张清单先分清

- 本机 LlamaIndex venv、Metal 等环境常识

### 0.2 本表实施范围（要排期）

- Agent 绑工单（非第二中枢）

## 2. 分周排期（建议从确认本计划日起算 Week 1）

### 第 1–2 周 · M0 门禁（P0）

| 任务 | 产出 | 负责人角色 |
|------|------|------------|
| L6 路径 A 按 checklist 走通并签字（或登记缺陷台账） | 签字页 / 缺陷列表 | 产品验收 + 开发陪跑 |
| 全量 pytest 再跑；红项进台账 | 绿或已知失败清单 | 开发 |
| 确认生产 alembic=0028、schema PASS（已做过可复查） | 记录 | 开发 |
| **不做什么**: SFT、图谱、新模块页面 | — | — |

### 第 2–5 周 · M1 事件壳 E1（P0）

| 任务 | 产出 |
|------|------|
| `economic_events` 等表 + Alembic + fix_legacy_db | 迁移 |
| `/api/economic-events` CRUD / 关联 / transition / steps | API |
| 前端 `/ledger/events` 列表+详情+时间轴 | UI |
| 分录列表显示所属事件（嵌入） | UI |
| 单测：非法状态迁移拒绝；查询不创建事件 | 测试 |
| 生产 apply_prod_schema + 审计 PASS | 运维 |

**验收**: 打开事件卡，能挂 1 分录+1 文件，steps 有记录。

### 第 3–6 周 · M2 开源增强（与 M1 后半并行）

| 任务 | 开源 | 产出 |
|------|------|------|
| Chat 结果 → Pydantic 字段 | Instructor | `ContractFields` / `IntentRoute` schema |
| 合同/制度切分检索 | LlamaIndex → 现有 Qdrant | 检索服务模块（非业务中枢） |
| Provider 仍走 OpenAI 兼容 / Ollama | 已有 | 配置不变 |
| **不引入**: LangChain 全栈、llama-cpp 双轨 | — | — |

**验收**: 上传合同 PDF → 抽出结构化字段建议 + 可检索相关片段。

### 第 5–8 周 · M3 合同双 Skill（P0 场景）

| 任务 | 产出 |
|------|------|
| 事件类型 `contract_compliance_review` / `contract_bookkeeping_prep` | 配置+枚举 |
| 意图路由（规则+LLM JSON） | 默认「风险摘要+缺件清单」 |
| Skill A：风险清单写入 steps | 不改总账 |
| Skill B：入账准备 → Staging/草稿建议 + 缺件状态 | 调用现有 API |
| 闸门：缺关键件不可 `posted` | 状态机规则 |
| Agent 入口：结果落工单而非纯聊天 | 实验 Agent 改造 |

**验收**: 普通人视角「上传合同 → 系统自己选路并推进下一动作 → 等人确认才过账」。

### 第 7–9 周 · M4 Tool 白名单（P1）

| 任务 | 产出 |
|------|------|
| 文档化主路径 API（导入/凭证/过账/事件） | Tool Catalog |
| deprecated 旁路不进 Agent | 配置 |
| 权限：Tool 级校验账簿 | 中间件/依赖 |

### 第 8–10 周 · M5 编排加固（可选）

| 任务 | 产出 |
|------|------|
| 若采用 LangGraph：节点只调领域服务，checkpoint≠业务真相 | 适配层 |
| 或继续纯自研状态机（也合格） | 二选一 |

### 第 9–12 周 · M6 工程化（按需）

| 任务 | 开源 | 触发条件 |
|------|------|----------|
| Redis + ARQ/RQ | 解析/向量经常拖死请求时 | 负载 |
| MinIO | 证据要备份/多机时 | 运维 |
| OTel / Sentry | 生产排障痛时 | 运维 |
